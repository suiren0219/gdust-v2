# 学习助手 0.1.5 登录回跳与网页重新检查

## 仓库协议核对

- 通用登录仍走 `passport2.chaoxing.com/login`，不固定学校；`refer` 改为已有业务入口 `ChxSso.HOME`（`mooc2-ans/visit/interaction`），不再回到通用个人首页。
- 每门课程的入口来自课程列表中的 `visit/stucoursemiddle` 链接，包含该门课的 courseId/classId/cpi；继续逐课读取正文、菜单与 enc/workEnc/t。作业列表、作业详情和任务点进度不互相替代。
- 课程进度继续使用已有 `mycourse/stu-job-info?clazzPersonStr=...` 协议按班级关联。作业请求不依据任务点数量跳过课程。
- 检索现有源码、文档和本机历史 HAR 未找到可确认的 9010 验证码协议定义。本轮按用户提供的现象增加兼容：仅 JSON 顶层 code/errorCode 明确等于 9010，或实际表单同时含 captcha/verifyCode/validateCode 输入与验证码/安全验证文案，提示人工网页验证。正文、课程编号或脚本模板中的 9010 不触发。

## 修改行为

- 从课程页打开登录或课程网页后，“完成检查”读取课程进度；从作业页打开后读取各门课作业。
- 不能只凭课程发现成功和 connected 状态关闭网页。仍有作业失败、进度失败或缓存保存错误时保留页面和错误提示。
- 验证码是读取受阻，不自动清除会话或缓存；不尝试解码验证码、不自动提交验证表单。
- 作业详情返回验证要求时，向上传递课程失败，不再作为缺少截止时间静默忽略。
- 再点“完成检查”重新读取课程参数和对应列表，不共用其他课程的签名。

## 回归范围

- 两门课程分别声明菜单与不同签名，断言各自请求的 enc/stuenc/Referer 正确。
- 验证码 JSON、真实验证表单识别，以及正文数字和脚本模板的反例。
- 详情验证受阻后再次读取，确认重新获取课程参数。
- 作业部分失败时网页检查不成功，验证后再次读取成功。
- 课程页网页检查只走课程进度，不读取作业。
