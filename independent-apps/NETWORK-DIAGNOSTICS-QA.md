# 学习助手 0.1.7 传输诊断与受限恢复

## 最终行为

- 所有学习通业务请求统一经过核心 `ChxHttpExchange`：网络故障只按固定类型（超时/域名/安全连接/连接/提前关闭/中断/HTTP2/协议/解压/传输）与阶段（等待响应头/读取正文）输出诊断，不保留异常原文、地址参数、Cookie 或代理信息。
- 仅 GET 在收到完整响应头之前因连接提前关闭或中断失败时，等待 1 秒后用全新连接池重试一次；POST、已收到响应后的正文失败、任何 HTTP 响应（含 429/401/跳转）都不重试。应用层的验证码暂停与 429 冷却规则不变，仍优先于任何重试。
- 429、401 与 3xx 只读响应头不读正文，Retry-After 不会因正文故障丢失；超过 4 MiB 的响应改为固定的“数据过大（BODY_TOO_LARGE）”失败，不再伪装成网络传输失败。
- 诊断行固定包含：类型 NET_*、阶段、HTTP 状态（或“未收到完整响应”）、协议与“新连接恢复 0/1 或 1/1”，并附请求方法与脱敏路由（已知主机 + 静态路径段；课程列表、进度接口路径已纳入）。
- 作业与课程页顶部错误卡新增“复制本次诊断”：复制当前版本号 + 本次失败的固定诊断；诊断在新一轮读取开始时清空，成功后不留旧失败，退出或账号变化一并清除。
- 学习助手与核心传输均保持关闭 OkHttp 连接失败隐式重试（`retryOnConnectionFailure(false)`）；WebView 页面自身资源请求不受业务闸门约束，与 0.1.6 一致。
