## 0.1.8 追加：提示页变体的验证码识别

- 使用真实账号在独立模拟器登录复测时确认：逐课课程页落地的是 processVerifyPng 提示页（正文“【9010】操作异常，请输入图片中的验证码”），验证码输入框名为 `ucode`。0.1.5–0.1.7 的表单识别只覆盖 captcha/verifyCode/validateCode 输入，漏判该变体，导致 55 门课程被逐课误报为“课程页缺少字段 courseid”而不是暂停。
- 修复后判定验证码页的条件：输入框 id/name 含 ucode（或原有三个字段）且正文提到验证码/安全验证；或正文同时出现 9010、操作异常与验证码。课程页正文单独提到 9010 或验证码不会误判（负例测试保留）。
- 真实账号验证：0.1.8（versionCode 9）覆盖安装后刷新作业，第一门课程落地 9010 提示页即暂停整轮读取，readControl 卡片出现“打开网页完成验证”；该入口在 WebView 中正确打开同一个验证码页（ucode 输入 + 提交）。验证码图片内容无法自动读取，人工输入验证码并提交后的恢复读取未在本轮证明，待用户在手机上复测。
- 测试共 141 项通过；签名包 learning-018-signed.apk，SHA-256：939b7dcf5118a36284ef3bb22469bce17d95987590e2f4299d5e3ca37b121879。

## 最终行为

- 学习助手的作业、课程进度共用一个请求闸门；业务接口串行执行，前一个请求完成后至少间隔 1 秒再发下一项。没有定时自动刷新或后台自动恢复。
- 已识别的验证码响应立即暂停后续业务请求，排队请求在发送前重新检查暂停状态。验证码仍由用户在官方网页手动完成，不自动识别或提交。
- HTTP 429 读取 Retry-After：支持秒数和 HTTP 日期；日期优先结合服务端 Date 计算等待时间。缺失或无效时默认 60 秒，至少等待 1 秒。超大秒数不会溢出为立即放行。
- 冷却到期只允许用户主动重查，不自动发请求；验证码暂停只允许“完成检查”开启一次恢复读取。恢复失败、再次触发验证或取消均不解除暂停。
- 暂停原因、冷却结束时间、受阻课程和剩余队列随账号加密快照保存；重开应用或清缓存不会直接绕过尚未结束的暂停。退出/账号变化清除旧账号状态。无唯一账号时仍只保存在进程内，不将数据写入其他账号缓存。
- 作业按课程逐项读取和保存。暂停时保留已读结果及旧缓存，未读课程保持未知；验证后先重新发现课程并重查受阻课程，成功后由用户点击“继续读取剩余课程”。
- 课程进度触发暂停时，恢复检查回到进度读取；不能从另一页刷新绕过。普通 403 和网络错误不冒充验证码或登录失效。
- 学习助手 HTTP 客户端与通用核心传输均关闭连接失败隐式重试。WebView 官方页面自身的资源请求仍由页面控制，未声称受到业务请求闸门限速。
